## Purpose

Обновление локальных клонов из TUI: fetch и pull только fast-forward через системный git, без интерактивных запросов, с понятными причинами пропусков и ошибок и отображением опережения/отставания от upstream.

## ADDED Requirements

### Requirement: Системный git как опциональная зависимость
Система SHALL искать git при старте (`git.path` или `PATH`, `git.enabled: false` отключает). Если git не найден или отключён, действия `u`/`U` SHALL быть скрыты из футера и хелпа, колонка ↑↓ пуста. Определение проекта, ветки и предпроверки SHALL читать файлы `.git`, а не вызывать git.

#### Scenario: Нет git
- **WHEN** git не найден в `PATH`
- **THEN** в футере workspace нет `u` и `U`, колонка ↑↓ пустая, остальное работает

### Requirement: Fetch
`u` SHALL выполнять `fetch --prune` по remote проекта во всех локальных репозиториях workspace (GitLab и серых не-GitLab), а в режиме проекта с локальной папкой — в этой папке. Подтверждение не требуется. В workspace из группы `u` SHALL быть скрыт.

#### Scenario: Fetch workspace
- **WHEN** в workspace с 13 репозиториями нажат `u`
- **THEN** запускается fetch во всех 13, рабочие копии не меняются

#### Scenario: Upstream на другом remote
- **WHEN** проект определён по `origin`, а у текущей ветки `branch.main.remote = upstream`, нажат `u` или `U`
- **THEN** скачиваются оба remote (`origin` и `upstream`), ↑↓ и fast-forward считаются по свежему `upstream/main`

### Requirement: Pull только fast-forward
`U` SHALL после confirm-модалки выполнять fetch, затем fast-forward текущей ветки до upstream, никогда не создавая merge-коммит и не оставляя репозиторий в состоянии конфликта. Перед запуском репозиторий SHALL пропускаться с причиной, если: detached HEAD; у ветки нет upstream; идёт merge или rebase. Confirm SHALL показывать, сколько репозиториев будет обновлено и сколько пропущено с причинами («обновить 11 репозиториев, пропустить 2 (detached, нет upstream)»). Разошедшаяся ветка и мешающие локальные изменения SHALL давать пропуск с причиной, а не ошибку посреди merge.

#### Scenario: Разошедшаяся ветка
- **WHEN** локальная ветка и upstream имеют разные новые коммиты, нажат `U` и подтверждён
- **THEN** репозиторий помечен `○ разошлась`, рабочая копия и HEAD не изменились

#### Scenario: Обычный pull
- **WHEN** upstream впереди на 3 коммита, локальных изменений нет
- **THEN** ветка сдвинута на 3 коммита, строка `✓ +3`, ветка в шапке перечитана

### Requirement: Запуск без терминала
Процессы git SHALL запускаться без управляющего терминала и без stdin, с запретом интерактивных запросов, так что нехватка авторизации даёт быструю ошибку, а не зависание и не перехват ввода TUI. Неинтерактивная авторизация (ssh-agent, Keychain, credential helpers) SHALL работать. Каждый репозиторий ограничен таймаутом `git.timeout` (60 с), одновременно — не больше `git.parallel` (6). Выход из TUI SHALL прерывать все процессы.

#### Scenario: Недоступный ssh-хост
- **WHEN** remote указывает на ssh-хост, который не отвечает
- **THEN** репозиторий получает `✗` не позже таймаута, TUI отзывчив всё это время

#### Scenario: Нет ключа
- **WHEN** ssh требует ключ, которого нет в агенте
- **THEN** `✗ нужна авторизация` с подсказкой «выполни git fetch в <папка> вручную», пароль не запрашивается

### Requirement: Результаты и ход операции
Каждый репозиторий SHALL получать статус: обновлено `✓` (pull — `✓ +N`), актуально (`✓` приглушённо), пропущено `○` с причиной, ошибка `✗` с причиной. Ошибки SHALL классифицироваться: нужна авторизация, сеть, разошлась, мешают локальные изменения, таймаут; иначе — последняя строка stderr как есть. Последние 20 строк вывода SHALL храниться для превью строки. Во время операции шапка любого экрана SHALL показывать `⟳ fetch 7/13` (или `pull`), строки таба «Проекты» — `◐`; по завершении — итоговый тост «fetch: 12 ✓, 1 ✗ (route-planner-ui: нужна авторизация)». Повторный `u`/`U` во время операции SHALL игнорироваться с тостом «fetch уже идёт». Операция SHALL продолжаться при переходах между экранами.

#### Scenario: Итог fetch
- **WHEN** fetch прошёл в 12 репозиториях и упал по авторизации в одном
- **THEN** тост «fetch: 12 ✓, 1 ✗ (route-planner-ui: нужна авторизация)», у строки `✗`, превью показывает причину и stderr

#### Scenario: Переход во время fetch
- **WHEN** во время fetch пользователь открыл проект через `f`
- **THEN** шапка проекта показывает `⟳ fetch 7/13`, по завершении приходит итоговый тост

### Requirement: Опережение и отставание
Система SHALL считать опережение и отставание текущей ветки от upstream локально (без сети): один раз в фоне при открытии workspace и после каждого fetch/pull, для всех репозиториев (не больше 8 одновременно). Значение SHALL показываться в колонке ↑↓ таба «Проекты» (`↓3 ↑1`, пусто при равенстве или без upstream) и в шапке режима проекта рядом с веткой (`fix/slot-race ↓3`). При `git.fetch_on_start: true` при открытии workspace SHALL запускаться фоновый fetch всех репозиториев.

#### Scenario: После fetch
- **WHEN** fetch принёс в upstream 3 новых коммита
- **THEN** в колонке ↑↓ строки `↓3`
