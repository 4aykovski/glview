## MODIFIED Requirements

### Requirement: Экран MR detail
`enter` на MR SHALL открывать экран деталей: крошки `<проект> › MRs › !<iid>`, заголовок MR, строка `author · source → target · <время> · +N −M в K файлах`, где `<время>` — `открыт <когда>` для открытого MR, `смержил <кто> <когда>` для смерженного (без `<кто>`, если GitLab его не вернул) и `закрыт <когда>` для закрытого; если нужной даты нет, показывается `открыт <когда>`, чипы статуса (mergeable-статус, апрувы, пайплайн, число неразрешённых тредов) и вкладки Overview, Diff, Discussions, Pipelines, Commits (в этом порядке), переключаемые `tab`/`shift+tab`. Значение `detailed_merge_status` SHALL показываться как есть, рядом — переведённая подпись. Для MR не в состоянии opened (GitLab отдаёт для них `not_open`) первый чип SHALL показывать состояние: `✓ merged` (роль Success), `○ closed` и `○ locked` (нейтральная роль), без подписи; цвет ошибки для них MUST NOT использоваться.

#### Scenario: Открытие MR
- **WHEN** пользователь нажал `enter` на !479 в списке
- **THEN** открыт экран !479 на вкладке Overview, `esc` возвращает к списку с курсором на !479

#### Scenario: Смерженный MR
- **WHEN** открыт MR в состоянии merged, `detailed_merge_status = not_open`
- **THEN** первый чип `✓ merged` в рамке Success, текста `not_open` на экране нет

#### Scenario: Когда смержен
- **WHEN** открыт MR, смерженный пользователем `d.orlov` 5 часов назад, язык ru
- **THEN** строка под заголовком содержит `смержил d.orlov 5ч назад` вместо `открыт … назад`

#### Scenario: Когда закрыт
- **WHEN** открыт MR, закрытый без слияния 3 дня назад, язык en
- **THEN** строка под заголовком содержит `closed 3d ago`

#### Scenario: Статус без перевода
- **WHEN** у MR `detailed_merge_status = not_approved`, язык ru
- **THEN** чип содержит `not_approved` и русскую подпись

#### Scenario: Порядок вкладок
- **WHEN** открыт MR с 3 изменёнными файлами, 2 тредами, 3 пайплайнами и 4 коммитами
- **THEN** строка вкладок — `Overview  Diff 3  Discussions 2  Pipelines 3  Commits 4`

## ADDED Requirements

### Requirement: Вкладка Diff
Вкладка Diff MR detail SHALL показывать изменения MR одной прокруткой: для каждого файла — заголовок `▾ <путь>` с `+A −D` справа (переименование `старый → новый`, пометки `новый`, `удалён`, `сгенерирован`), затем ханки: заголовок `@@ … @@` (Muted), строки с колонками старого и нового номера (Muted), знаком и текстом; добавленные — `+` ролью Success, удалённые — `-` ролью Error. Табы SHALL раскрываться в 4 пробела, длинные строки MUST NOT переноситься: `←/→` сдвигают текст кода на 8 колонок, номера остаются на месте. Заголовок вкладки SHALL быть `Diff N`, где N — число файлов загруженного диффа, до загрузки — `MergeRequest.Diff.Files`, если известен.

#### Scenario: Файл с изменениями
- **WHEN** в MR файл `internal/slots/alloc.go` с ханком `@@ -40,3 +40,4 @@`: контекст, удалённая строка, две добавленные
- **THEN** вкладка показывает `▾ internal/slots/alloc.go` с `+2 −1`, строку `@@ -40,3 +40,4 @@`, у контекстной строки номера `40 40`, у удалённой — только старый `41` и знак `-`, у добавленных — только новые `41`, `42` и знак `+`

#### Scenario: Переименование и новый файл
- **WHEN** в диффе переименованный `docs/old.md → docs/metrics.md` и новый файл `cmd/tool/main.go`
- **THEN** заголовки `▾ docs/old.md → docs/metrics.md` и `▾ cmd/tool/main.go  новый`

#### Scenario: Горизонтальный скролл
- **WHEN** строка кода шире экрана и пользователь нажал `→` дважды
- **THEN** текст кода сдвинут на 16 колонок, колонки номеров на месте

#### Scenario: Ширина 80
- **WHEN** терминал 80×24, открыта вкладка Diff
- **THEN** ни одна строка не шире 80 колонок, строк не больше высоты

### Requirement: Курсор и сворачивание на вкладке Diff
Курсор вкладки Diff SHALL стоять на строке (заголовок файла, заголовок ханка, строка кода, строка треда): `j/k` по строкам, `J/K` — к заголовку следующего/предыдущего файла, `g/G`, `pgdown`/`pgup`, `ctrl+d`/`ctrl+u`. `space` на любой строке файла SHALL сворачивать или разворачивать файл (курсор — на его заголовок), `z` — сворачивать все, если хоть один развёрнут, иначе разворачивать все. Сгенерированные файлы и файлы, дифф которых скрыт сервером (`too_large`, `collapsed`), SHALL быть свёрнуты по умолчанию; выбор пользователя SHALL сохраняться при обновлении по пути файла, курсор — на том же файле и номере строки, если они остались.

#### Scenario: Переход по файлам
- **WHEN** курсор на строке кода первого из трёх файлов и пользователь нажал `J`
- **THEN** курсор на заголовке второго файла

#### Scenario: Свернуть файл
- **WHEN** курсор на строке кода файла и пользователь нажал `space`
- **THEN** файл показан одной строкой `▸ <путь>`, курсор на ней

#### Scenario: Дифф скрыт сервером
- **WHEN** у файла `too_large: true` и пустой `diff`
- **THEN** файл свёрнут с пометкой `слишком большой`; развёрнутый показывает «дифф скрыт GitLab — o откроет файл в браузере»

#### Scenario: Бинарный файл
- **WHEN** у файла пустой `diff` без флагов скрытия
- **THEN** под заголовком строка «нет текстового диффа»

#### Scenario: Сворачивание переживает обновление
- **WHEN** пользователь развернул сгенерированный файл и нажал `r`
- **THEN** после ответа файл развёрнут, курсор на той же строке

### Requirement: Загрузка диффа
Дифф SHALL загружаться лениво: при первом переходе на вкладку Diff или при открытии MR через `d`; дальше — по `r` (после ответа деталей MR) и при смене head SHA MR; тики поллинга MUST NOT запрашивать дифф. Ключ кэша SHALL содержать head SHA (TTL 10 мин). Пока идёт загрузка — строка `◐ загружаем дифф…`; пустой дифф — «Нет изменений»; ошибка — тост, повтор по `r` или повторному входу на вкладку.

#### Scenario: Лениво
- **WHEN** MR открыт на Overview и пользователь не открывал Diff
- **THEN** в журнале фейка нет вызова `Diffs`; после `tab` на Diff — один вызов

#### Scenario: Пуш в MR
- **WHEN** вкладка Diff открыта и очередной ответ деталей MR принёс новый head SHA
- **THEN** дифф запрошен заново один раз

#### Scenario: Тик без изменений
- **WHEN** вкладка Diff открыта, тик поллинга, head SHA прежний
- **THEN** вызова `Diffs` нет

### Requirement: Треды на строках диффа
Diff-треды, строка которых нашлась в текущем диффе (по `new_path`/`new_line`, у удалённой строки — по `old_path`/`old_line`), SHALL показываться под своей строкой по строке на тред: `●` (Warning) у неразрешённого или `✓` (Muted) у разрешённого, автор, время, первая строка первой заметки (обрезка `…`), `N ответов`. `enter` на строке треда SHALL переключать на Discussions, делать этот тред текущим, разворачивать и прокручивать к нему. Треды, строку которых не нашли, на Diff MUST NOT показываться.

#### Scenario: Тред под строкой
- **WHEN** у MR неразрешённый тред anna.k на `internal/slots/alloc.go`, новая строка 42, с одним ответом
- **THEN** под строкой 42 строка `● anna.k · 2h · <первая строка> · 1 ответ`

#### Scenario: Переход к треду
- **WHEN** курсор на строке треда и пользователь нажал `enter`
- **THEN** открыта вкладка Discussions, этот тред текущий (толстая рамка) и развёрнут

#### Scenario: Устаревший тред
- **WHEN** тред указывает на строку 300, а в файле диффа такой строки нет
- **THEN** на Diff его нет, в Discussions он есть

### Requirement: Комментарий к строке
`c` на строке кода вкладки Diff SHALL открывать форму комментария (3.16) с заголовком `Комментарий · !<iid> · <путь>:<строка>` (новый номер, у удалённой — старый). Отправка SHALL создавать тред с позицией: `position_type=text`, SHA из `MergeRequest.DiffRefs`, `old_path`/`new_path` файла, `new_line` у добавленной, `old_line` у удалённой, оба у контекстной. На прочих строках вкладки и при неизвестных `DiffRefs` `c` SHALL открывать обычный комментарий к MR. После успеха discussions перезапрашиваются. Ответ 400 SHALL давать тост с текстом GitLab и подсказкой «обнови (r)», текст формы MUST сохраняться.

#### Scenario: Комментарий к добавленной строке
- **WHEN** курсор на добавленной строке 42 файла `internal/slots/alloc.go`, пользователь нажал `c`, ввёл текст и отправил
- **THEN** вызван `CommentLine` с `NewPath = OldPath = internal/slots/alloc.go`, `NewLine = 42`, `OldLine = 0` и SHA из `DiffRefs`; после ответа discussions перезапрошены, под строкой 42 новый тред

#### Scenario: Контекстная строка
- **WHEN** комментарий к контекстной строке со старым номером 40 и новым 40
- **THEN** в позиции `OldLine = 40` и `NewLine = 40`

#### Scenario: Не строка кода
- **WHEN** курсор на заголовке файла и пользователь нажал `c`
- **THEN** открыта обычная форма комментария к MR (`Комментарий · !479 …`), отправка — `Comment`

#### Scenario: Строка ушла из диффа
- **WHEN** `CommentLine` вернул 400 с сообщением сервера
- **THEN** тост с этим сообщением и «обнови (r)», форма открыта с прежним текстом

#### Scenario: Черновик к строке
- **WHEN** пользователь начал комментарий к строке 42, закрыл форму `esc`, потом нажал `c` на строке 43
- **THEN** форма для строки 43 пустая; `c` снова на строке 42 восстанавливает черновик

### Requirement: Ссылка на файл диффа
`o` на вкладке Diff SHALL открывать в браузере `<ссылка MR>/diffs#<sha1(new_path)>` файла под курсором, `y` — копировать её; до загрузки и на пустом диффе — `<ссылка MR>/diffs`.

#### Scenario: Ссылка файла
- **WHEN** курсор на строке файла `internal/slots/alloc.go` и пользователь нажал `y`
- **THEN** скопирована ссылка `<ссылка MR>/diffs#` + hex SHA1 от `internal/slots/alloc.go`
