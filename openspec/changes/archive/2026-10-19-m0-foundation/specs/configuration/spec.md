## Purpose

Хранит настройки gitlab-tui (инстанс, токен, язык, параметры) и определяет, с каким хостом и каким токеном работать, включая токен из glab.

## ADDED Requirements

### Requirement: Расположение и формат конфига
Система SHALL читать конфиг из `$XDG_CONFIG_HOME/gitlab-tui/config.yaml`, а при пустом `XDG_CONFIG_HOME` — из `~/.config/gitlab-tui/config.yaml` на всех ОС, включая macOS. Флаг `--config` SHALL переопределять путь. Отсутствие файла MUST NOT быть ошибкой.

#### Scenario: Конфига нет
- **WHEN** файла конфига не существует
- **THEN** используются значения по умолчанию (`language: en`, `theme: terminal`) и запуск продолжается

#### Scenario: Битый YAML
- **WHEN** файл конфига содержит синтаксическую ошибку
- **THEN** запуск продолжается со значениями по умолчанию, пользователь видит предупреждение с номером строки

### Requirement: Безопасная запись конфига
Система SHALL записывать конфиг с правами `0600`, сохраняя существующие комментарии и порядок ключей. Если файл содержит токен и его права шире `0600`, система SHALL показать предупреждение.

#### Scenario: Сохранение языка
- **WHEN** пользователь переключает язык, а в конфиге есть комментарии
- **THEN** в файле меняется только `language`, комментарии остаются, права файла `0600`

#### Scenario: Широкие права
- **WHEN** конфиг с токеном имеет права `0644`
- **THEN** при старте показывается предупреждение о правах

### Requirement: Цепочка определения хоста
Система SHALL выбирать хост GitLab в порядке: хост из URL в `-p` → `host` из конфига → env `GITLAB_HOST` → хост remote текущего репозитория. Если хост не найден, система SHALL перейти к первичной настройке.

#### Scenario: Хост из remote
- **WHEN** конфига и `GITLAB_HOST` нет, а remote `origin` указывает на `gitlab.example.com`
- **THEN** используется `https://gitlab.example.com`

### Requirement: Цепочка определения токена
Система SHALL искать токен для выбранного хоста в порядке: `token` из конфига → env `GITLAB_TOKEN` → glab. Система MUST запоминать источник токена (config, env, glab) для подсказок и MUST NOT выводить токен в лог, интерфейс или stdout.

#### Scenario: Токен из env
- **WHEN** в конфиге токена нет, а `GITLAB_TOKEN` задан
- **THEN** используется токен из env, источник — env

#### Scenario: Токен нигде не найден
- **WHEN** токена нет ни в конфиге, ни в env, ни в glab
- **THEN** открывается экран первичной настройки

#### Scenario: Debug-лог
- **WHEN** включён `--debug` и выполняются запросы с токеном
- **THEN** в лог-файле токен замаскирован

### Requirement: Токен из glab
Если glab найден в PATH (или по `glab.path`) и `glab.enabled` не `false`, система SHALL запрашивать у glab токен для хоста. Сначала используется прямой запрос значения из конфига glab, затем — статус авторизации с выводом токена (для токенов в keyring). Каждый вызов glab MUST иметь таймаут 3 с и не читать stdin. Токен из glab MUST NOT сохраняться в конфиг gitlab-tui.

#### Scenario: Токен в конфиге glab
- **WHEN** glab залогинен на хост и хранит токен в своём конфиге
- **THEN** gitlab-tui использует этот токен, источник — glab

#### Scenario: glab не установлен
- **WHEN** glab не найден
- **THEN** шаг пропускается без ошибки

#### Scenario: glab завис
- **WHEN** вызов glab не завершился за 3 с
- **THEN** вызов прерывается, цепочка идёт дальше
