## ADDED Requirements

### Requirement: Таб Issues проекта
Таб Issues SHALL показывать issues проекта страницами по 20 (REST, `order_by=updated_at&sort=desc`, подгрузка за 5 строк до конца) с колонками IID (`#1318`), Title (+ `→ !479`, если известен связанный MR; несколько — `→ !479 +1`), Labels, Upd. Таб SHALL загружаться при первом открытии, обновляться поллингом раз в 30 с и по `r` мимо кэша; курсор держится на том же issue. Счётчик таба — общее число issues текущего фильтра (`X-Total`), статус футера — `<позиция> / <всего>`. Пустой список SHALL объяснять причину: «Нет открытых issues»; с фильтром «я» — «Нет открытых issues, назначенных тебе · m — снять фильтр «я»»; с прочими фильтрами — «Нет issues по фильтрам · backspace — сбросить». Для issues страницы с `merge_requests_count > 0` связанные MR SHALL запрашиваться в фоне (`related_merge_requests`, не больше 4 одновременно, кэш 5 минут; тики поллинга при живом кэше не перезапрашивают); маркер `→ !479` в списке SHALL показываться только для MR, закрывающих issue. Экран issue SHALL запрашивать связанные MR всегда, без проверки `merge_requests_count`.

#### Scenario: Список с связанным MR
- **WHEN** открыт таб Issues, у `#1312` один связанный MR `!479`
- **THEN** строка `#1312  Duplicate slot assignment under load → !479  bug slots  1h`, запрос связанных MR ушёл только для issues с `merge_requests_count > 0`

#### Scenario: Лениво
- **WHEN** открыт проект, таб Issues ни разу не открывался
- **THEN** запросов issues не было; первый переход на `3` запрашивает первую страницу

### Requirement: Фильтры issues
Строка фильтров `/` SHALL работать как у MR (`key:value`, подсказки ключей и значений, свободный текст — поиск) с ключами `state` (`opened` по умолчанию, `closed`, `all`), `assignee` (`any` по умолчанию, `@me`, `none`, участники проекта с поиском на сервере), `label` (список меток проекта, все сразу), `milestone` (`any` по умолчанию, `none`, активные milestones проекта с поиском на сервере). Без открытия строки: `s` SHALL переключать `state` по кругу opened → closed → all, `m` — `assignee` между `any` и `@me` (фильтр «я»), `backspace` — сбрасывать фильтры к умолчаниям. `o` SHALL открывать `<проект>/-/issues` с текущими фильтрами (умолчания не пишутся; `@me` — логин текущего пользователя, если известен), `O` — выделенный issue, `y` — копировать ссылку выделенного issue.

#### Scenario: Фильтр «я»
- **WHEN** на табе Issues нажат `m`
- **THEN** в строке фильтров `assignee:@me`, запрос issues с `scope=assigned_to_me`

#### Scenario: Milestone из подсказок
- **WHEN** в строке фильтров набрано `milestone:2026`, через 300 мс пришли подсказки, выбрана `2026-Q4`, нажат `enter`
- **THEN** запрос issues с `milestone=2026-Q4`, `o` открывает `<проект>/-/issues?milestone_title=2026-Q4`

### Requirement: Превью issue
Превью выбранного issue SHALL показываться справа при ширине от 140 колонок (вертикальный разделитель, как в макете), иначе снизу по правилам превью таба MRs, а если не помещается — не показываться. Содержимое: title; строка `● open · #1318 · anna.k · assignee: egor · milestone: 2026-Q4` (закрытый — `○ closed`, отсутствующие части не пишутся); связанные MR, если загружены; описание в markdown (HTML комментариев GitLab переводится в markdown) не выше половины превью с обрезкой `…`, пустое — «нет описания»; `КОММЕНТАРИИ N` и последние комментарии (без системных заметок), сколько влезает целиком, каждый — `author · время` и тело не длиннее 6 строк; внизу — `c — написать комментарий…`. Комментарии SHALL запрашиваться лениво для выбранного issue (последние 50 заметок); ответ для другого issue выбрасывается; ошибка — «комментарии недоступны» без тоста.

#### Scenario: Широкий терминал
- **WHEN** ширина терминала 150, выбран `#1318` с двумя комментариями
- **THEN** превью справа: title, строка статуса, описание, `КОММЕНТАРИИ 2`, оба комментария, `c — написать комментарий…`

#### Scenario: Курсор ушёл до ответа
- **WHEN** курсор переведён с `#1318` на `#1312` до ответа заметок `#1318`
- **THEN** ответ для `#1318` выброшен, превью ждёт заметок `#1312`

### Requirement: Экран issue
`enter` на issue SHALL класть на стек экран issue с шапкой `<проект> › Issues › #<iid>`: title, строка статуса, метки, связанные MR (всегда отдельным запросом), описание в markdown и треды комментариев карточками — так же, как вкладка Discussions в MR detail (системные заметки скрыты, сворачивание, текущий тред — толстая рамка Accent). Экран — одна прокрутка: `j/k`, `pgdown/pgup`, `ctrl+d/ctrl+u`, `g/G`; `J/K` — следующий/предыдущий тред с прокруткой к нему; `space` — свернуть/развернуть текущий тред. `c` — комментарий, `x` — close/reopen, `o` — issue в браузере, `y` — ссылка issue, `esc` — назад к списку с тем же курсором. Экран SHALL обновляться поллингом раз в 30 с (на вершине стека) и по `r`, сохраняя прокрутку и свёрнутость тредов. Нет комментариев — «Комментариев нет · c — написать».

#### Scenario: Открытие и возврат
- **WHEN** на `#1318` нажат `enter`, затем `J`, затем `esc`
- **THEN** открыт экран `#1318` со всеми тредами, после `J` текущий — первый тред; после `esc` таб Issues с курсором на `#1318`

### Requirement: Закрытие и переоткрытие issue
`x` на открытом issue (в табе и на экране issue) SHALL показывать confirm «Закрыть issue #<iid>?» с title в описании, по умолчанию «Отмена»; подтверждение закрывает issue (`state_event=close`). `x` на закрытом SHALL переоткрывать его сразу, без confirm. Успех — тост «Issue #<iid> закрыт» / «Issue #<iid> открыт снова» и перезагрузка (в табе с `state:opened` закрытый issue пропадает, курсор — на соседней строке); ошибка — тост ошибки. У архивного проекта `c` и `x` MUST NOT показываться и действовать.

#### Scenario: Закрытие из таба
- **WHEN** на открытом `#1318` нажат `x`, выбрано «Да»
- **THEN** фейк получил `SetState(#1318, closed)`, тост «Issue #1318 закрыт», `#1318` пропал из списка `state:opened`

#### Scenario: Отмена по умолчанию
- **WHEN** нажат `x`, затем `enter`
- **THEN** запроса нет

#### Scenario: Переоткрытие без confirm
- **WHEN** при `state:closed` на `#1260` нажат `x`
- **THEN** confirm не показан, фейк получил `SetState(#1260, reopen)`, тост «Issue #1260 открыт снова»

### Requirement: Форма комментария
`c` SHALL открывать модальную форму комментария к объекту (issue или MR) с заголовком `Комментарий · #1318 <title>` (для MR — `!479 <title>`), многострочным полем ввода (markdown как есть), подсказкой `markdown · tab — к кнопке · alt+enter — отправить` и низом `esc закрыть` / кнопка `enter Отправить`. `tab`/`shift+tab` SHALL переключать фокус между полем и кнопкой; в поле `enter` — перенос строки, `alt+enter` — отправка; на кнопке `enter` — отправка. Пустой (из пробелов) комментарий MUST NOT отправляться: строка «комментарий пуст». Во время отправки форма заблокирована, «отправляем…», `esc` не действует. Успех — форма закрыта, тост «Комментарий добавлен», экран перезапрашивает комментарии; ошибка — тост, форма остаётся с текстом. `esc` SHALL закрывать форму без отправки, сохраняя черновик в памяти сессии; повторный `c` на том же объекте восстанавливает его, успешная отправка стирает. Ответы закрытой формы MUST NOT попадать в новую форму.

#### Scenario: Комментарий к issue
- **WHEN** на `#1318` нажат `c`, набрано «Беру», нажат `tab`, затем `enter`
- **THEN** фейк получил `Comment(#1318, "Беру")`, тост «Комментарий добавлен», в превью новый комментарий

#### Scenario: enter в поле не отправляет
- **WHEN** в поле набрано «строка», нажат `enter`
- **THEN** в поле две строки, запроса нет

#### Scenario: Черновик
- **WHEN** набран текст, нажат `esc`, затем снова `c` на том же issue
- **THEN** поле содержит прежний текст

#### Scenario: Ошибка отправки
- **WHEN** GitLab ответил 403 на комментарий
- **THEN** тост «Недостаточно прав», форма открыта с текстом и разблокирована
