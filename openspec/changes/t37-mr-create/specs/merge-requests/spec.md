## ADDED Requirements

### Requirement: Форма New MR
`n` в табе MRs SHALL открывать экран-форму `<проект> › MRs › новый MR` с полями: из ветки, в ветку, строка состояния веток, заголовок, флажок Draft, шаблон, описание, assignees, reviewers, labels, milestone, флажки «удалить ветку после merge» и squash, предпросмотр и кнопка `enter Создать`. Пока форма открыта, глобальные хоткеи MUST NOT действовать. `tab`/`shift+tab` SHALL переводить фокус по кругу; форма выше экрана SHALL прокручиваться так, что поле в фокусе и его подсказки видны; минимальный размер — 80×24.

#### Scenario: Открытие в режиме проекта
- **WHEN** локальная ветка `feat/surge` есть на сервере, default-ветка `main`, пользователь нажал `n` в табе MRs
- **THEN** «Из ветки» — `feat/surge`, «В ветку» — `main`, фокус на «Из ветки»

#### Scenario: Глобальные хоткеи выключены
- **WHEN** фокус в поле заголовка и пользователь ввёл `T`, `p`, `q`
- **THEN** символы попали в заголовок, экраны и оверлеи не открылись

#### Scenario: 80×24
- **WHEN** терминал 80×24, фокус на milestone, en и ru
- **THEN** ни одна строка не шире 80 колонок, поле milestone и его подсказки видны

### Requirement: Ветки и их проверка
Поля веток SHALL подсказывать ветки проекта (поиск через 300 мс, до 5). Через 300 мс после смены любой ветки SHALL показываться строка состояния: `N коммитов · M файлов` (сравнение target…source), Warning «нет изменений», если коммитов ноль, Warning «ветки … нет на сервере — сначала git push», если ветки нет на сервере, Muted «N коммитов не запушены — в MR их не будет», если `localgit` знает ↑ у локальной ветки, Warning «из … уже открыт !N», если открытый MR из ветки есть. Ответы для прежней пары веток MUST выбрасываться.

#### Scenario: Сравнение
- **WHEN** source `feat/surge` опережает `main` на 3 коммита в 5 файлах
- **THEN** строка состояния `3 коммита · 5 файлов`

#### Scenario: Ветка не запушена
- **WHEN** локальная ветка `feat/new` есть, а на сервере её нет
- **THEN** «Из ветки» — `feat/new`, строка состояния — Warning «ветки feat/new нет на сервере — сначала git push»

#### Scenario: Дубль
- **WHEN** из `feat/surge` уже открыт !482
- **THEN** строка состояния содержит «из feat/surge уже открыт !482»

#### Scenario: Смена ветки во время проверки
- **WHEN** проверка `feat/a` ещё идёт, пользователь сменил ветку на `feat/b`
- **THEN** ответ для `feat/a` выброшен, показано состояние `feat/b`

### Requirement: Заголовок, Draft и описание
Заголовок по умолчанию SHALL быть заголовком единственного коммита сравнения, иначе именем ветки, где `-` и `_` заменены пробелом, а первая буква заглавная; заголовок следует за ветками, пока его не правили. Флажок Draft SHALL добавлять `Draft: ` к заголовку при создании, если заголовок ещё не начинается с `Draft:`, `[Draft]` или `(Draft)` (без учёта регистра). Шаблон `Default` (без учёта регистра) SHALL подставляться в пустое описание при открытии; смена шаблона при описании, правленом после подстановки, SHALL спрашивать confirm «Заменить описание шаблоном «X»?».

#### Scenario: Один коммит
- **WHEN** в сравнении один коммит `Fix race in courier slot allocator`
- **THEN** заголовок — `Fix race in courier slot allocator`

#### Scenario: Несколько коммитов
- **WHEN** source `feat/surge-pricing`, коммитов 3
- **THEN** заголовок — `Feat/surge pricing`

#### Scenario: Draft
- **WHEN** заголовок `Fix slot race`, Draft включён, пользователь создал MR
- **THEN** `Create` получил title `Draft: Fix slot race`

#### Scenario: Шаблон по умолчанию
- **WHEN** у проекта шаблоны `Default` и `Bug`
- **THEN** при открытии поле «Шаблон» — `Default`, описание — содержимое `Default`

#### Scenario: Замена правленого описания
- **WHEN** пользователь дописал описание и выбрал шаблон `Bug`
- **THEN** confirm «Заменить описание шаблоном «Bug»?»; «Отмена» оставляет описание

### Requirement: Участники, метки, milestone и флажки
Assignees и reviewers SHALL выбираться чипами из участников проекта (поиск через 300 мс, до 5, первой строкой `@me`), labels — из меток проекта, milestone — одно значение из активных milestones; `backspace` в пустом поле убирает последний выбранный. Флажок «удалить ветку после merge» SHALL по умолчанию следовать `remove_source_branch_after_merge` проекта, squash — `squash_option` (`default_on` — включён, `default_off` — выключен, `always`/`never` — включён/выключен и заблокирован). Предпросмотр SHALL показывать `будет создан: <src> → <target>` и непустые части (draft, assignee, reviewers, labels, milestone).

#### Scenario: @me первым
- **WHEN** фокус в поле Assignees с пустым вводом
- **THEN** первая подсказка — `@me` (текущий пользователь)

#### Scenario: Squash по настройке проекта
- **WHEN** у проекта `squash_option = always`
- **THEN** флажок squash включён и не переключается `space`, рядом «по настройке проекта»

#### Scenario: Предпросмотр
- **WHEN** выбраны assignee egor, два ревьюера, одна метка, Draft
- **THEN** предпросмотр `будет создан: feat/surge → main · draft · assignee egor · reviewers 2 · labels 1`

### Requirement: Создание MR
`enter` на кнопке SHALL запоминать снимок полей и проверять: ветки не пусты и различаются, заголовок не пуст (ошибка — строкой над кнопкой, фокус в поле); состояние веток для снимка получено (иначе ждать с «проверяем ветки…», `esc` прерывает); ветка есть на сервере и коммитов больше нуля (иначе ошибка, создания нет); открытого MR из ветки нет — иначе confirm «Из <src> уже открыт !N «title». Открыть его?» (по умолчанию «Да» — открыть MR detail !N вместо формы). Затем SHALL вызываться `Create` со снимком; пока идёт — форма заблокирована, «создаём…», `esc` не действует. Успех: тост «MR !N создан», кэши списков MR проекта и групп workspace сброшены, форма заменена MR detail нового MR. Ошибка: тост с текстом GitLab, форма с теми же значениями.

#### Scenario: Успех
- **WHEN** форма заполнена корректно и пользователь нажал `enter` на кнопке
- **THEN** вызван `Create` со снимком, затем открыт MR detail нового MR; `esc` возвращает в список MR, где новый MR виден после перезапроса

#### Scenario: Нет изменений
- **WHEN** сравнение дало 0 коммитов и пользователь нажал `enter` на кнопке
- **THEN** ошибка «нет изменений: feat/surge не опережает main», `Create` не вызван

#### Scenario: Дубль — открыть
- **WHEN** из ветки уже открыт !482, пользователь нажал `enter` на кнопке и подтвердил «Да»
- **THEN** `Create` не вызван, открыт MR detail !482

#### Scenario: Ошибка сервера
- **WHEN** `Create` вернул 422 с сообщением сервера
- **THEN** тост с этим сообщением, форма открыта с прежними значениями и разблокирована

#### Scenario: Ответ закрытой формы
- **WHEN** пользователь закрыл форму, пока шла проверка веток, и открыл её снова
- **THEN** ответ первой формы во вторую не попал

### Requirement: Черновик New MR
`esc` SHALL закрывать форму, сохраняя значения в памяти до конца сессии по ключу хост + проект; повторный `n` в том же проекте SHALL восстанавливать их и перезапускать проверки; успешное создание SHALL стирать черновик. На диск черновик MUST NOT писаться.

#### Scenario: Восстановление
- **WHEN** пользователь ввёл заголовок, нажал `esc`, затем снова `n` в том же проекте
- **THEN** заголовок и выбранные поля на месте, строка состояния веток запрошена заново
