## Что в макетах обязательно

Реализация повторяет макет по раскладке и тексту:

- порядок блоков: шапка → табы → строка фильтров → заголовок колонок → строки → превью → футер;
- горизонтальные разделители там, где в макете `border-bottom`/`border-top` (под табами, под заголовком колонок, над футером, между шапкой экрана и контентом), вертикальные — между колонками панелей (описание MR | правая колонка, список | превью issue);
- рамки у превью, у колонок стейджей в Pipeline (активная колонка — акцентной рамкой, downstream — пунктиром), у чипов статуса MR, у модалок и полей форм;
- счётчики в табах (`1 MRs 6`, `Discussions 2`), префикс `/` в строке фильтров и все ключи фильтров со значениями (`ref:any`);
- набор и порядок колонок, выравнивание чисел и длительностей вправо, маркер `›` и выделение строки;
- в логе: номера строк отдельной тусклой колонкой, длительность секции справа, строка поиска отдельной полосой над футером;
- правая часть футера — последний тост или статус экрана.

## Что в макетах иллюстративно

- **Цвета.** Hex-значения условные. В реализации — только 16 ANSI-цветов через роли `Theme` (SPEC §9): `#E9A23B` → Accent, `#8A919C` → Muted, `#262A31` → Border, зелёный/красный/синий/фиолетовый → роли статусов. Фон выделенной строки в терминале — reverse (SPEC §9.2), а не цветной фон.
- **Шрифт и размеры.** Терминал моноширинный, один размер: крупный заголовок MR — это Bold.
- **Верхняя полоса** `gitlab-tui — ~/src/route-service` — заголовок окна терминала, не часть интерфейса.
- **Хоткеи и вкладки, отменённые в SPEC.** Приоритет у SPEC §3.1 («Отличия от макетов (MVP)» и «Разрешённые конфликты»): нет `d` diff, вкладок Diff/Commits, `a` артефакты, `ctrl+s` star; merge — `M`, «мои/все» — `m`, в Run pipeline — `a`/`d` вместо `ctrl+a`/`ctrl+d`.
- **Служебные подписи** в правой части футера макетов («huh form», «sections из section_start», «jobs + bridges») — пояснения для читателя макета, не текст интерфейса.
